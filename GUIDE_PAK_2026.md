# Guide : mod .pak pour le règlement 2026 dans F1 Manager 24

Installation détectée : `F:\SteamLibrary\steamapps\common\F1 Manager 2024`

## Ce qui est déjà installé chez toi

| Élément | Où | Rôle |
|---|---|---|
| UE4SS | `F1Manager24\Binaries\Win64\ue4ss` | Scripts Lua et dump des mappings |
| Mod « DRS mod » (TheFireNexus) | `ue4ss\Mods\DRS mod` | **Visuel seulement** : anime l'aileron arrière et l'aileron avant quand `DRSState == 3`. Ne change pas la performance |
| RRacing26 / RRacing26SMZ / RRacingV5 | `Content\Paks\RRacing*_P.*` | Mod 2026 existant (SMZ veut sûrement dire *Straight Mode Zones*) |
| IndividualCarMods | `Content\Paks\IndividualCarMods` | Livrées et châssis 2026 (Audi, Cadillac, etc.) |

> **Avant de tout refaire** : RRacing26SMZ fait peut-être déjà le Straight Mode. Ouvre-le dans FModel (étape 3) pour voir quels fichiers il modifie. Ça t'indique exactement quels assets toucher. Inspecte-le pour apprendre, mais ne redistribue pas son contenu sans l'accord de l'auteur.

### Ce qu'on a vu dans les mods RRacing (avec `retoc`)

- `RRacing26SMZ` : non chiffré mais **sans noms de fichiers** (index retiré). Il contient **24 packages**, soit probablement un fichier par circuit du calendrier. Ça confirme que les zones du Straight Mode sont définies **circuit par circuit**.
- `RRacing26` et `RRacingV5` : **chiffrés avec la clé de l'auteur**. On ne peut pas les inspecter, et on respecte ce choix.

## Important : le jeu utilise IoStore

Les fichiers sont des `.utoc` + `.ucas` (et un petit `.pak`). **UnrealPak seul ne suffit pas.** Il faut un outil qui sait recréer des `.utoc`/`.ucas` : **retoc**.

## 1. Outils à installer

| Outil | Rôle | Source |
|---|---|---|
| **FModel** | Parcourir et extraire les fichiers du jeu | github.com/4sval/FModel |
| **UAssetGUI** | Modifier les `.uasset` (DataTables, courbes) | github.com/atenfyr/UAssetGUI |
| **retoc** | Convertir IoStore ↔ legacy et créer le mod `.utoc/.ucas` | github.com/trumank/retoc |

## 2. Générer les mappings (.usmap) avec UE4SS

Le jeu utilise des propriétés « non versionnées ». Sans fichier `.usmap`, FModel et UAssetGUI ne peuvent pas lire les valeurs.

1. Lance le jeu et va jusqu'au menu principal.
2. Appuie sur **Ctrl + Pavé num. 6** (raccourci par défaut d'UE4SS « Generate .usmap »).
3. Le fichier apparaît dans `Binaries\Win64\` (ou `ue4ss\`) sous le nom `Mappings.usmap`.
4. Copie-le dans `C:\Users\andyd\Documents\DEV\NewReg2026\tools\Mappings.usmap`.

## 3. Explorer les fichiers avec FModel

1. *Settings* → *Game directory* : `F:\SteamLibrary\steamapps\common\F1 Manager 2024\F1Manager24\Content\Paks`
2. *UE Versions* : **GAME_UE5_1**.
3. *Mapping file* : coche « Local » et pointe vers ton `Mappings.usmap`.
4. **Clé AES obligatoire** : les fichiers du jeu sont chiffrés (vérifié avec `retoc info`). Récupère la clé AES de F1 Manager 2024 auprès de la communauté de modding (Discord F1 Manager Modding, guides sur Overtake.gg), puis entre-la dans *Directory* → *AES*. Pour retoc, il faut l'ajouter avec `-a 0x...`.
5. Recherche (Ctrl+Shift+F) de ces mots-clés :
   - `DRS` : effet du DRS (réduction de traînée), seuil d'écart (1,0 s), zones
   - `ERS`, `Energy`, `Battery`, `Deploy`, `Harvest` : modes ERS, puissance, capacité
   - `Overtake`, `Attack` : mode attaque ERS
   - `Track`, `Circuit` + nom d'un circuit : données de piste avec les zones DRS
6. Pour voir ce que modifie RRacing26SMZ : clic droit sur `RRacing26SMZ_P.utoc` → la liste des fichiers montre ce qu'il remplace.
7. Exporte chaque asset utile (*Export Raw Data* → `.uasset` + `.uexp`) dans `NewReg2026\extract\`, **en gardant l'arborescence** (`F1Manager24\Content\...`).

**Le jeu de base charge mal avec retoc si les `.pak` sont dans le dossier** (plantage AES). Solution utilisée : `F:\NewReg2026_paks_tmp` contient des liens physiques vers les seuls `global`/`pakchunk*` `.utoc`/`.ucas`. Commande d'extraction :
```bash
retoc -a <CLE_AES> to-legacy --no-shaders --no-script-objects -f <NomDuFichier> F:\NewReg2026_paks_tmp extract\legacy
```

## 4. Adapter les règles 2026

| Règle 2026 | Ce qu'on modifie | Valeur indicative |
|---|---|---|
| **Straight Mode** (aéro active) | Seuil d'activation DRS → très grand (tout le monde l'a) | 999 s au lieu de 1,0 s |
| | Zones DRS sur toutes les grandes lignes droites de chaque circuit | 1 zone par ligne droite |
| | Gain de traînée du DRS → un peu plus faible (c'est pour tout le monde) | environ 70 % de la valeur d'origine |
| **Overtake Mode** | Mode ERS d'attaque : plus de puissance, vidange plus rapide | +50 % de puissance de déploiement |
| **ERS 350 kW** | Puissance de déploiement max | environ 3× la valeur 2024 (120 → 350 kW) |
| **Récupération** | Taux de récupération (harvest) par tour | environ 2× (jusqu'à 8,5 MJ/tour) |
| **Plus de MGU-H** | Pas de recharge « gratuite » en ligne droite | réduire la récupération en mode neutre |

Dans UAssetGUI :
1. *Utils* → *Import Mappings* → ton `.usmap`, et choisis la version **5.1**.
2. Ouvre le `.uasset` dans `extract\`, modifie les valeurs, puis *File* → *Save*.
3. Garde une note de chaque valeur d'origine (dans `notes_valeurs.md`) pour pouvoir équilibrer ensuite.

## 5. Repaqueter

> **Attention : `retoc to-zen` seul fait planter le jeu au démarrage.** Le moteur du jeu (UE 5.1 « volta24 ») attend des en-têtes de package et un index de conteneur différents de ceux que retoc écrit (1 groupe d'export par package au lieu de 2, et la liste des dépendances). Utilise **`scripts\build_install.ps1`**. Il reprend les en-têtes et l'index d'origine du jeu et ne remplace que les données (voir `scripts\build_raw.py`). Ça ne marche que si la taille des données ne change pas (modification de valeurs uniquement).
>
> Pour tester une variante sans risque : `pwsh scripts\test_variant.ps1 -Name <variante>`. Le script lance le jeu, détecte un plantage dans les 60 s, puis ferme le jeu.

Ancienne méthode, gardée pour mémoire :

Structure du dossier à packer :
```
NewReg2026\mod\F1Manager24\Content\...   (tes .uasset/.uexp modifiés)
```

Commande (à vérifier avec `retoc --help`, la syntaxe peut changer selon la version) :
```bash
retoc to-zen --version UE5_1 mod zzz_Reg2026_P.utoc
```

Copie ensuite les fichiers `zzz_Reg2026_P.pak`, `.utoc` et `.ucas` dans `Content\Paks\`.

- Le suffixe **`_P`** est obligatoire (fichier « patch » chargé par-dessus le jeu).
- Le préfixe **`zzz_`** fait charger ton mod après les autres, pour qu'il gagne en cas de conflit avec RRacing26.

## 6. Tester

1. Lance une course rapide (pas ta carrière).
2. Vérifie : DRS ouvert sur toutes les lignes droites pour toute la grille, et l'aileron qui s'anime (via le « DRS mod »).
3. En cas de crash au lancement : retire `zzz_Reg2026_P.*`, puis reprends un asset à la fois.

## 7. Étape suivante : un vrai Overtake Mode via UE4SS

Le mod DRS montre qu'on peut lire `CarData` en Lua (`CarData.DRSState`, `CarData.TeamName`). Un script peut :
- lire l'écart avec la voiture de devant ;
- si l'écart est < 1 s, forcer le mode ERS d'attaque ou ajouter de l'énergie batterie.

Il faut d'abord trouver les bons noms de champs. Avec la console UE4SS ou un dump d'objets (`Dump all objects` dans UE4SS), on cherche ce qui contient `ERS`, `Battery`, `Gap` dans `CarData`.
